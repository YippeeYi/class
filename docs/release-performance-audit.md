# 发布前性能审查（2026-09-19）

## 结果与范围

保持业务表结构、权限模型、90 天滑动刷新、365 天绝对过期、私有 Storage 和既有视觉样式。沿用已部署的业务版本迁移，没有新增第二套认证或状态管理。`frontend/src/components/ui` 没有改动。

审查覆盖路由与初始化、数据服务、页面 Hook、ArchiveProvider、缓存、图片签名与尺寸、后台预读、字体、图标、构建和管理上传。主要修复：首次业务读取与版本检查的竞态、阻塞页面的整页插图尺寸扫描、解锁题库时批量下载预览、旧上传脚本无效的 HTTP 缓存指令，以及失效的 GitHub 仓库链接。

## 缓存分层

| 类型 | 保存与刷新规则 |
| --- | --- |
| 认证 | 原邀请码存储与服务器校验；业务刷新完全不写入 |
| 业务数据 | 内存去重 → sessionStorage → 按访问范围隔离的 IndexedDB；首次先共享一次版本请求；版本变化后后台重取 |
| 图片尺寸 | 独立非业务缓存；只在图片即将显示时读取；四并发、请求超时、失败退避 |
| 图片签名 | 当前文档内存去重，四并发；原有 180/600 秒有效期，退出清理，不写入持久存储 |
| 图片与静态文件 | 浏览器 HTTP 缓存；保留已解码原图、背景缓存；不因业务版本变化清除 |
| GitHub Stars | 独立 localStorage key；30 分钟新鲜期、失败五分钟退避、四秒请求超时；不发送邀请码或 Cookie |

网站没有注册新的 Service Worker。原有清理整个站点的逻辑仅属于用户退出/凭证失效路径，业务版本更新不会调用它。

## 图片与首屏

- 书面页使用 1200 像素预览，题图 960，插图 720，头像 384，地图 1600；原图仍只在查看大图时加载。
- 相邻书面页只预取最多两张缩略图，背景选择只用小预览，选中后解码原图。`/qb` 本身约 12 KB，保持原资源，避免额外转换成本。
- 删除 RouteIllustrationGate 及其整页扫描、等待、缓存与订阅；导航意图仅预载目标代码块。个别图片仍通过公共尺寸服务先确定比例，避免弹出框改变大小。
- 隐藏题权限和按键序列保持不变；数据解锁后即可选择题型，只有当前题图读取尺寸与缩略图。
- 保留原有统计等页面动态导入、生产压缩与 tree shaking。没有新增 UI 库；现有依赖中由只读 shadcn 组件使用的包没有误删。

## 实测

浏览器回归使用固定测试数据及真实 Chromium，网络故障/延迟由测试拦截器模拟。数字用于验证请求行为，不作为真实用户网络的速度承诺。

| 场景 | 结果 |
| --- | --- |
| 测试记录页首次进入 | 1 次版本检查、4 项业务读取；并发组件不重复请求 |
| 完整刷新，版本未变 | 1 次版本检查、0 次业务读取 |
| 清除测试 session 缓存后重开 | 命中 IndexedDB，0 次业务读取 |
| 服务端版本更新后重开 | 每项业务数据只重取一次，无旧数据请求在先的浪费 |
| 版本接口 503 | 已有缓存继续显示，凭证保留 |
| 多标签页 | 隐藏标签页最终同步、页面节点保留、图片与静态缓存保留 |
| 生产构建受控样本 | 45 项资源；CLS 0、无长任务；单次 LCP 388 ms（本地测试环境） |
| 线上书面页抽样 | 原图 1,632,381 字节，预览 167,101 字节，1200×1800，减少约 89.8% |
| 线上同源重复图片请求 | Chromium Network 确认 1 次缓存命中；签名响应通过 Expires 控制缓存 |

生产 JS 总 gzip 从前轮约 435 KB 降到约 434 KB；统计大模块仍按页面加载。主要收益来自取消无关图片请求与重复数据下载，而非激进拆包。

## Storage 缓存维护

旧上传逻辑使用裸值 `Cache-Control: 3600`，现改为有效的 `private, max-age=180/600`。这与签名响应使用 Expires 是两个不同层面；不能仅因签名响应缺少 Cache-Control 就判定没有缓存。

`npm run admin -- storage-cache` 只读检查，追加 `--apply` 修复旧值：逐个备份线上字节与元数据、检查版本、原样写回、核对实时列表中的缓存头、大小与 MD5。备份在被 git 忽略的 `private-assets/backups/storage-cache-*`。不会发布本地数据、改变文件内容或设置公开桶。修复可重复执行，完成对象自动跳过。

同一路径可能被覆盖，因此不使用永久 immutable 缓存。即时替换应采用新资源路径。签名继续仅在原有效期内复用，不为缓存扩大访问窗口。参考 [Supabase 缓存说明](https://supabase.com/docs/guides/storage/cdn/smart-cdn)。

## GitHub 入口

入口位于导览右上公共卡片区；图标、间距和状态复用 GuidePanel。配置集中在 `frontend/src/lib/github-project.ts`。旧 `YippeeYi/classRecord` 官方接口返回 404，现使用 Git 远程对应的真实公开仓库 `YippeeYi/class`。

当前 Lucide 1.x 不包含品牌图标，使用其官方旧版 GitHub 路径和现有 createLucideIcon 渲染器，未引入另一图标库；许可保存在 `frontend/public/third-party-notices.txt`。数字来自官方 stargazers_count，缓存/限流/延迟/键盘外链和卡片高度均有测试。

## 检查入口

- `npm run check`：环境、数据库迁移、内容审计、类型、lint、单元测试、构建与体积预算。
- `npm run test:app`：所有页面、认证、移动端、业务版本、GitHub 入口及故障降级。
- `npm run test:layout`：浅深色、320/390/768/1280 宽度、1.25/2 DPR、图片替换与滚动。
- `npm run test:pages`：`/class/` 基础路径和深层页面直接访问/刷新。
- `CLASS_RECORD_LIVE_RELEASE=1 node scripts/test-live-release.mjs`：真实临时邀请码/会话，九表版本触发器与权限检查，完成后清理测试凭证。
- `node scripts/measure-image-performance.mjs`：只读线上原图/预览大小与浏览器 HTTP 缓存，不输出密钥、签名 URL 或图片内容。
