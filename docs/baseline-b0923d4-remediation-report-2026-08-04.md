## 3. 本轮发现并修复的代码级问题

1. 全局图片元数据预加载器会在每个受保护路由强制加载记录、人物和派生名言，放大首屏网络与 CPU 开销。
2. 记录列表依赖全局 archive 聚合资源，必须等待与当前页面无关的人物、名言数据。
3. 普通记录视图也会请求书面页、留言和补充资料。
4. 每次搜索输入都会重复解析全部正文标记，并重复构造年月日选项。
5. 筛选条件被写入列表容器 `key`，导致每次筛选整棵记录列表卸载重建。
6. 记录卡片和引用回调缺少稳定边界，父页面更新会扩大重渲染范围。
7. 各页面在正文区重复显示大标题，顶部栏只有品牌名，造成留白和信息层级重复。
8. 首页“历史上的今天”固定在左上角，可能压住导航层。
9. 背景遮罩和内容表面透明度不统一，用户背景被过度遮挡。
10. 资料页虽已有双滚动区，但重复页头和偏保守的宽度/内距压缩了有效阅读面积。
11. 页头动作最初采用桌面/移动双实例隐藏方案；代码复核后改为 `matchMedia` 单实例响应式挂载，避免重复 ID、隐藏控件和重复副作用。

## 4. 性能改进

- 普通记录首屏从“记录 + 人物 + 派生名言 + 书面页 + 留言 + 补充”的聚合等待，收敛为单独 `loadRecords()`。
- 书面页、留言和补充仅在 `view=written` 时并发加载。
- 删除全局跨页面元数据爬取；记录页只在空闲期预热最多 16 个首屏候选插图，其余图片在 pointer/focus/touch 意图或页面自身加载链路中按需取尺寸。
- 普通记录页只在空闲期预热最新记录中的最多 16 个插图路径，并限制并发为 3。
- 正文搜索文本使用记录对象级 `WeakMap` 缓存；日期选项使用 `useMemo`，不随搜索词重算。
- 移除筛选容器动态 `key`；`RecordCard` 使用 `memo`，引用跳转使用稳定 `useCallback` 与最新状态引用。
- 构建仍按路由拆包；生产构建转换 2,817 个模块，记录页产物约 15.47 kB（gzip 6.34 kB）。

这些是确定性的请求依赖和渲染范围削减。由于本轮没有可用的普通用户访问令牌，未把开发环境网络波动下的单次计时包装成性能百分比。

## 9. 未完成项、风险与建议

仍有两项边界没有被误报为已闭环。第一项是“普通最终用户 token → RPC 复验 → RLS → 私有 Storage 签名 → 真实数据逐页交互”的 A 类浏览器验收。本轮没有读取或消耗邀请码文件，也没有把私有令牌、签名 URL 或资源写入代码/日志。类型、测试、生产构建、公共门禁和代码级数据链路均已验证，但它们不能替代这条最终授权链路。第二项是用户要求中的字面“React Aria 下拉框”：当前项目 `components.json` 明确采用 shadcn `base-nova`，只读的 shadcn Select 实际封装 `@base-ui/react/select`，而不是 React Aria。业务代码已经全部统一到这套 shadcn Select，没有原生或手写下拉；在“不得修改 `frontend/src/components/ui`”约束下，本轮没有擅自引入第二套下拉实现或改写 CLI 组件。

建议在发布前使用一枚有效普通邀请码执行一次只读验收，重点覆盖：记录列表/书面视图切换、资料双滚动区、背景切换、人物/名言来源定位、答题、时间线和蹭饭图大图。若该验收通过，本轮不存在已知功能欠缺；若失败，应优先判断为环境/RLS/数据契约问题，再回到对应 F01、F05、F07、F15、F16、F20 项定位。

若“React Aria”指的是必须使用该底层库，而不只是要求无原生控件、完整键盘/弹层/焦点语义，则后续需要一次明确的 UI registry 迁移决策：允许用 shadcn CLI 将整套 Select 从 Base UI 变体迁移到 React Aria 变体，并重新验证所有依赖它的页面。只改业务层包装会形成两套组件源，与当前 shadcn 配置及只读目录规则冲突，因此不建议作为静默修补处理。

## 10. 2026-08-05 统计页专项复核与收口

### 10.1 旧版结构与现版偏差

旧版 `timeline.html` 的阅读顺序是“总览指标 → 整体记录人占比/全档案月趋势 → 年度记录人占比/年份选择 → 月度记录人占比/月度选择 → 月度摘要 → 每日柱形图 → 七列日历 → 记录人图例与洞察”。专项复核发现，重构初版虽保留了数据能力，但存在四项结构偏差：

1. 全档案月趋势给图表写入动态 `minWidth`，外层再启用 `overflow-x-auto`，因此页面主动制造了横向滚动区域。
2. 年份控件同样使用水平滚动容器，月份分布与月份选择被拆开，破坏旧版“左图右选项”的连续阅读关系。
3. 年度区域额外插入一张柱形图，使总览、年份、月份三个层级不再清晰。
4. 指标、年份或月份变化时，页面根节点使用动态 `key` 整体卸载重建；饼图同时叠加 Recharts 浮动 `Tooltip` 与 550ms 动画，首次悬停时内容测量和位置过渡叠加，造成提示框或周边视觉元素跳动。

源码中没有“上三角形—横线—下三角形”对应的业务组件、图标导入或事件处理。它不是一个遗漏功能，而是强制滚动容器在浏览器/操作系统中生成的滚动条附属视觉。删除制造溢出的宽度与容器后，该图案随根因一并消失。

### 10.2 专项修复

- 统计页恢复旧版层级和左右配对布局：整体占比/全档案趋势、年度占比/年份选择、月度占比/月度选择；删除无基准依据的年度附加柱形图。
- 全档案和每日柱形图改为固定高度、`width: 100%`、`min-width: 0` 的响应式容器，不再给数据点数量换算像素宽度；年份和月份改为会自动换行的语义化按钮网格。
- 日历恢复桌面七列、窄屏四列；年份和月份卡头在手机端上下排列，操作按钮不再挤压标题。
- 饼图回归旧版稳定交互：保留常驻图例与扇区高亮，移除无基准依据的浮动提示框。柱形图仍保留精确值提示，但关闭 Tooltip 位置动画并固定内容宽度；饼图入场动画从 550ms 降至 320ms。
- 删除统计页、人物页、人物列表、名言页、搜索页用于筛选状态的根节点动态 `key`，避免每次切换把整个结果树卸载重建。
- 统计聚合新增记录日期、字符数、人物/名言提及、参与者和记录人 `WeakMap` 缓存；一次性构造年/月索引并复用于指标卡、图表、日历和洞察，减少重复正文解析和重复筛选。
- 统计页单独获得 90rem 可用宽度；其他普通页面保持原有上限。没有改动只读目录 `frontend/src/components/ui`。
- 页面标题继续统一进入顶栏；人物详情同时在顶栏与正文 `h1` 显示当前姓名，加载期使用等高“人物资料”标题，直接 URL 进入时不再先显示上一个页面标题。
- “不要外传”只在首页/引导页显示；记录页和蹭饭图不再重复。首页使用可见但克制的隐私提示，蹭饭图仅保留“班级私有资源”标签。
- 背景表面、正文透明度、字号、行高和资料阅读宽度沿用本轮统一方案，统计页新增内容也使用同一套卡片层级和排版尺度。

当前 [Recharts Tooltip 文档](https://recharts.github.io/en-US/api/Tooltip/)说明提示层支持位置动画，[ResponsiveContainer 文档](https://recharts.github.io/en-US/api/ResponsiveContainer/)要求由可收缩容器提供尺寸；本次实现据此关闭柱形图 Tooltip 的位置动画，并移除固定最小宽度。[shadcn Chart 文档](https://ui.shadcn.com/docs/components/chart)推荐由外层提供明确高度并让图表容器占满宽度，本次柱形图按该组合方式落地。

### 10.4 剩余真实环境边界

当前内置浏览器没有普通用户授权状态，Chrome/Edge 扩展浏览器也不可用，因此受保护的 `/timeline` 会按设计跳转到 `/auth`。本轮没有读取邀请码、检查浏览器凭据存储、伪造 session 或加入开发绕过。统计页的数据计算、交互结构、响应式契约、类型、测试和生产构建均已闭环；仍需在发布前使用一枚有效普通邀请码完成一次真实数据只读验收，重点观察首次图例悬停、年份/月切换、每日图表与日历、记录来源跳转以及四个目标视口是否仍无横向滚动。

构建还显示现有 `GoogleSansFlex` 可变 TTF 为 3,997.14 kB，并使用 `font-display: swap` 避免阻塞文字显示。当前工作区没有可验证的 WOFF2 无损转换/字形覆盖检查工具，因此本轮没有用不完整子集冒险替换它；后续应在字体许可允许的前提下，用可复现的字体流水线生成 WOFF2，并对中文回退、拉丁字形、变量轴和浏览器兼容性做视觉回归。

## 11. 2026-08-05 最终差异复核与资源收口

## 18. 2026-08-12 实体与精确称呼感知的填空修复

本轮再次逐函数对照旧版 `quizApp.js` 的 `extractTokenRefs`、`buildBaseQuestion`、`renderRecordWithBlank`、`blankHtml` 与当前 `quiz-engine.ts`、`markup.ts`、`QuizMarkupContent`。旧版题目以引用标记生成答案，但显示阶段只对剥离标记后的字符串执行一次 `replace`，无法安全表达“同实体同称呼全部同步、其他同文不受影响”。当前迁移实现则存在双重扩大匹配：安全 AST 先把同 ID 的不同别名都改成答案文本，React 渲染器再对每个文本节点执行 `split(blankAnswer)`，因此会误挖同实体别名、异实体同名和普通正文同名。

最终题目模型只传递 `{kind,id,label}` 一份目标语义，不再重复保存 `blankAnswer`。标记安全化时逐引用节点比较引用类型、实体 ID 和 NFC 后的精确可见称呼；仅三者同时相同的每个节点被转换为显式 `blank` 节点，其他引用只安全展平其可见内容。渲染器不再全局切分文本，也不按字符数猜占位宽度；实际答案字形从首帧即参与行内排版，未揭示时只将前景涂制为透明，揭示后只切换语义色和轻量表面，不改变宽高、基线、行高或换行。表格宽度统计同样把 `blank.answer` 纳入可见尺寸计算，避免表格题揭示后列宽变化。

自动回归现已覆盖：同人同称呼一次/多次、同人不同别名、异人同展示文、普通正文同字符串、名言同样的实体边界、句首/句中/句尾、相邻、跨行、标点、嵌套样式与表格。Playwright 对三个同目标空位在揭示前后的相对 X/Y、宽、高及题体总高逐项比较，容差 0.5 CSS px；1280/768/390/320px 布局回归与旧版其他标记、背景、人物、统计、导览合同同组通过。

全站控制台审计还暴露出导览页“浏览记录/搜索档案”两个 shadcn Button 使用 Link 作为渲染节点时仍保留 `nativeButton=true`，Base UI 因语义不一致持续报警。业务层已与时间线和正文链接的现有模式一致，显式设置 `nativeButton={false}`，并新增静态契约和浏览器 warning/error 监听；只读 `frontend/src/components/ui` 目录仍为零修改。
